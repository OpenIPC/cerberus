# OpenIPC Cerberus

[English](README.md) | **Русский** | [简体中文](README.zh-CN.md)

[![CI](https://github.com/OpenIPC/cerberus/actions/workflows/ci.yml/badge.svg)](https://github.com/OpenIPC/cerberus/actions/workflows/ci.yml)
[![Release](https://img.shields.io/github/v/release/OpenIPC/cerberus)](https://github.com/OpenIPC/cerberus/releases/latest)
[![License](https://img.shields.io/badge/license-Prosperity%203.0-blue)](LICENSE.md)
[![Platform](https://img.shields.io/badge/platform-OpenIPC-brightgreen)](https://openipc.org)

Облачный агент для камер с прошивкой [OpenIPC](https://openipc.org): маленький демон на C, который
живёт **внутри камеры** и включает её в приватную WireGuard-сеть — так, что видео, ONVIF, настройки и
SSH доступны откуда угодно, а между камерой и облаком нет ничего, кроме туннеля.

Делает ровно пять вещей:

1. заводит ключевую пару X25519 и claim-код — один раз, на первом старте;
2. энроллится в координатор по TLS (`POST /enroll`) и забирает join-материал;
3. кладёт ключ, claim-код и join-материал в **U-Boot environment** через `fw_setenv` — единственное
   место на камере, которое переживает перепрошивку;
4. поднимает `wg0` и следит за туннелем с двух сторон: возраст хендшейка из `wg` **и** ICMP-проба хаба
   *внутри* туннеля — свежий хендшейк на мёртвом пути выглядит как живой;
5. шлёт живость через `POST /nodes/{id}/heartbeat` и применяет то, что приезжает в ответе:
   сменившийся join-материал и одноразовые команды.

Единственная зависимость — **mbedTLS**, всё остальное — libc. Агент рулит kernel WireGuard, который в
прошивке уже есть, поэтому статически весит несколько сотен килобайт, а не целый userspace-WireGuard.

## Установка

Одна строка по SSH на камере, с токеном энролла из панели облака (панель выдаёт эту команду уже
заполненной):

```sh
curl -fsSL https://github.com/OpenIPC/cerberus/releases/latest/download/install.sh | sh -s -- tok_...
```

Установщик выбирает сборку под процессор камеры, сверяет её с `SHA256SUMS` из того же релиза, ставит
`/usr/sbin/cerberus`, даёт ему записать `/etc/init.d/S99cerberus`, пишет адрес и токен в U-Boot env и
запускает агента.
Перезагрузка не нужна. Если что-то не так, он печатает короткий код — `cerberus: E13` — и страницу, где
код расшифрован: <https://cloud.openipc.ru/docs/openipc-camera/#codes>.

Снять всё обратно:

```sh
curl -fsSL https://github.com/OpenIPC/cerberus/releases/latest/download/install.sh | sh -s -- --uninstall
```

`uninstall.sh` из того же релиза тоже работает и делает ровно это — он оставлен ради команд,
напечатанных до того, как два скрипта стали одним.

То же самое руками:

```sh
# cerberus-arm, cerberus-mipsel, ... — см. «Релизы» ниже
curl -fsSL -o /usr/sbin/cerberus https://github.com/OpenIPC/cerberus/releases/latest/download/cerberus-arm
chmod +x /usr/sbin/cerberus
cerberus init-script                   # пишет /etc/init.d/S99cerberus, запускающий этот бинарь
fw_setenv cerberus_api https://cloud-api.openipc.ru/v1
fw_setenv cerberus_enrollment_token tok_...
/etc/init.d/S99cerberus restart
```

Токен, выписанный в панели на одну камеру, привязывает камеру к тому, кто его выписал. С токеном
партии агент печатает claim-код (его же показывает `cerberus status`), который вводят в панели, чтобы
забрать камеру себе.

## Релизы

Релиз один — [`latest`](https://github.com/OpenIPC/cerberus/releases/latest), с заголовком
`Cerberus <версия>`; он публикуется заново при каждой смене версии. В нём — по одному **статическому** бинарю на архитектуру процессора: musl и mbedTLS внутри,
поэтому неважно, какая libc и какой mbedTLS в конкретной прошивке и есть ли он там вообще:

| `uninstall.sh`     | старый адрес `install.sh --uninstall`, оставлен ради уже напечатанных команд                                    |

## Что должно быть на камере

| нужно                       | зачем                                | если нет                                                             |
|-----------------------------|--------------------------------------|----------------------------------------------------------------------|
| kernel WireGuard + `wg`     | весь data plane                      | агент бесполезен                                                     |
| `ip`                        | адрес и линк на `wg0`                | то же                                                                |
| `fw_setenv` / `fw_printenv` | хранилище, переживающее перепрошивку | фолбэк в файл (и он не переживёт)                                    |

| `curl` с TLS                | установщик                           | скачать файлы руками                                                 |

## Настройка

`S99cerberus` читает U-Boot env и передаёт агенту переменными `CERBERUS_*`:

| ключ U-Boot                 | переменная                  | по умолчанию                                      | смысл                                                                |
|-----------------------------|-----------------------------|---------------------------------------------------|----------------------------------------------------------------------|
| `cerberus_api`              | `CERBERUS_API`              | —                                                 | база координатора, включая `/v1`                                     |
| `cerberus_enrollment_token` | `CERBERUS_ENROLLMENT_TOKEN` | —                                                 | одноразовый токен от владельца                                       |
| `cerberus_hostname`         | `CERBERUS_HOSTNAME`         | —                                                 | имя, под которым камера появится в панели                            |
| `cerberus_ca`               | `CERBERUS_CA`               | `/etc/ssl/certs/ca-certificates.crt`              | файл или каталог доверенных CA                                       |
| `cerberus_iface`            | `CERBERUS_IFACE`            | `wg0`                                             | интерфейс WireGuard                                                  |
| `cerberus_subnet`           | `CERBERUS_SUBNET`           | `10.80.0.0/16`                                    | только фолбэк: подсеть сети приезжает в join-материале               |
| `cerberus_heartbeat`        | `CERBERUS_HEARTBEAT`        | `20`                                              | секунд между heartbeat; `0` — выключить                              |
| `cerberus_ping_target`      | `CERBERUS_PING_TARGET`      | хаб                                               | кого пинговать внутри туннеля                                        |
| `cerberus_ping_interval`    | `CERBERUS_PING_INTERVAL`    | `60`                                              | секунд между пробами; `0` — выключить                                |
| `cerberus_ping_timeout`     | `CERBERUS_PING_TIMEOUT`     | `3`                                               | сколько секунд ждать ответа на пробу                                 |
| `cerberus_ping_fails`       | `CERBERUS_PING_FAILS`       | `3`                                               | неотвеченных проб подряд до пересборки интерфейса                    |
| `cerberus_events`           | `CERBERUS_EVENTS`           | `1`                                               | события движения; `0` — без хука и без событий                       |
| `cerberus_snapshot_url`     | `CERBERUS_SNAPSHOT_URL`     | `http://127.0.0.1/image.jpg?width=640&height=360` | кадр majestic; `http://user:pass@127.0.0.1/…`, если он просит пароль |

`cerberus_ca` важнее, чем кажется: в прошивке может не быть бандла CA вовсе, и тогда энролл падает на
сертификате координатора, а поправить это без перепрошивки нечем — укажите путь к корневому
сертификату (ISRG Root X1 для Let's Encrypt).

Переменные, которые читает только агент: `CERBERUS_STORE` (`auto` \| `uboot` \| `file:/path`),
`CERBERUS_STALE_AFTER` (`180`, секунд без хендшейка до перетыкания пира), `CERBERUS_RETRY_MIN` /
`CERBERUS_RETRY_MAX` (`5` / `300`, отступ повторов энролла), `CERBERUS_INSECURE=1` (без проверки TLS,
только для отладки), `CERBERUS_DRY_RUN=1` (печатать команды `ip`/`wg`, а не выполнять),
`CERBERUS_MOTION_HOOK` (`/usr/sbin/motion.sh`), `CERBERUS_MOTION_QUIET` (`10`, секунд тишины, после
которых эпизод кончился), `CERBERUS_MOTION_MAX` (`600`, через столько секунд эпизод обрывается, что бы
ни происходило), `CERBERUS_PIDFILE` (`/var/run/cerberus.pid`), `CERBERUS_SEED`
(`/etc/cerberus/seed`, случайность, сохранённая между запусками, чтобы запуск не ждал ядро),
`CERBERUS_RANDOM_DEV` (`/dev/urandom`), `CERBERUS_GETRANDOM=0` (не спрашивать сначала getrandom(2)).

```
cerberus run       # enroll + up + watch (по умолчанию; это запускает S99cerberus)
cerberus enroll    # только энролл, идемпотентно
cerberus up        # поднять интерфейс из сохранённого
cerberus status    # что сохранено, возраст хендшейка, отвечает ли туннель
cerberus keygen    # напечатать пару ключей (stdout — данные, диагностика в stderr)
cerberus clean     # убрать агента: интерфейс, автозапуск, сохранённое и сам бинарь
cerberus motion    # сказать работающему агенту «движение», как это делает хук majestic
cerberus snapshot  # взять один кадр с CERBERUS_SNAPSHOT_URL в /tmp/cerberus-snapshot.jpg
cerberus init-script [PATH|-]  # записать init-скрипт, запускающий этот бинарь [/etc/init.d/S99cerberus]
```

### Раньше — `streq_*`

До этого репозитория ключи назывались `streq_*`, а переменные — `STREQ_*`. Камеры, поставленные
тогда, продолжают работать, делать ничего не нужно:

- на старте агент копирует свои ключи — ключ устройства, claim-код, join-материал — из `streq_*` в
  `cerberus_*`, проверяет каждую копию и дальше пишет только новые имена;
- копии `streq_*` **остаются на месте**, поэтому старый `S99cerberus` или старый бинарь, на который
  кто-то откатился, по-прежнему находят рабочую камеру;
- `S99cerberus` читает `cerberus_<имя>`, а при его отсутствии — `streq_<имя>`, так что настройки по
  старым инструкциям действуют; переменные `STREQ_*` тоже принимаются;
- сброс энролла (отозванный узел), `cerberus clean` и `install.sh --uninstall` стирают оба имени, поэтому
  старая копия не может воскресить отозванный узел;
- когда копировать больше нечего, старт не пишет во флеш ничего.

## Как это устроено

### Что где лежит

Ключ устройства, node id, overlay-адрес, адрес и ключ хаба, allowed IPs, подсеть сети, overlay-адрес
хаба и claim-код — всё в U-Boot env.

**Ключ там же, и это осознанно.** На камере `/etc` — это squashfs или оверлей на разделе, который
перепрошивка перезаписывает, а node id в U-Boot env её переживает. Камера, сохранившая node id и
потерявшая ключ, вернулась бы с личностью, которую хаб знает, и без ключа, которым её доказывают, — а
энролл пропускается всегда, когда node id сохранён. Ключ и node id обязаны жить и умирать вместе.
`wg set private-key` хочет путь, поэтому на время ровно одного вызова ключ пишется в `/tmp` (0600) и
сразу удаляется; на rootfs он не попадает никогда.

### Control plane: REST

Полноценные узлы держат SignalR-соединение с координатором. Клиент такого на C — не тот жанр, поэтому
камера ходит в REST-двойники: heartbeat раз в `CERBERUS_HEARTBEAT` секунд, и ответ на него — весь её
обратный канал:

```jsonc
{
  "command": "None",          // None | Restart | Reboot — одноразовая, выдаётся ровно один раз
  "join": {                   // текущий join-материал, всегда целиком, а не дельта
    "kind": "Wireguard", "overlayIp": "10.80.0.7",
    "hubEndpoint": "hub.example:51820", "hubPublicKey": "base64…", "allowedIps": "10.80.0.7/32"
  },
  "mapVersion": 42
}
```

`join` агент сверяет с сохранённым и применяет **только расхождение**: хаб переехал или сменил ключ —
камера перезаписывает стор и перепрограммирует интерфейс сама. `Restart` — это re-exec агента,
`Reboot` — `sync` и `reboot`. `404` на heartbeat значит, что координатор узел больше не знает: агент
выбрасывает энролл и останавливается, чтобы следующий старт зашёл заново, а не долбился мёртвым node id
до конца времён.

### Присмотр за туннелем

Свежий хендшейк не значит рабочий туннель: WireGuard переустанавливает его раз в две минуты, даже
когда по туннелю не ходит ничего — забранный маршрут, интерфейс, который занял кто-то другой, хаб,
который ничего не форвардит. Только вернувшийся пакет говорит «туннель работает». Лестница
восстановления — по возрастанию цены, и камера проходит её сама:

| что видно                                    | что делается                                      |
|----------------------------------------------|---------------------------------------------------|
| хендшейку больше `CERBERUS_STALE_AFTER`      | перетыкается пир (это же и перерезолвит имя хаба) |
| `CERBERUS_PING_FAILS` проб подряд без ответа | интерфейс сносится и собирается заново            |
| вдвое больше — пересборка не помогла         | агент перезапускает сам себя                      |

От недоступного координатора `cerberus run` тоже не умирает: init на камере запускает его один раз и
больше не смотрит, поэтому энролл повторяется с удваивающейся паузой сколько понадобится.

### События движения

Движение majestic замечает сам, когда в нём включена детекция движения (веб-интерфейс → Majestic →
Детекция движения), и запускает `/usr/sbin/motion.sh`. Этот скрипт ставит cerberus — если там уже
лежал чужой, он сохраняется как `motion.sh.orig` и по-прежнему вызывается, — и скрипт ничего не
делает, кроме как будит агента. Агент собирает вызовы в эпизоды (движение, затем
`CERBERUS_MOTION_QUIET` секунд тишины) и сообщает о каждом дважды, `started` и `ended`, в
`POST /nodes/{id}/events`.

Если владелец включил для камеры детекцию объектов, ответ на `started` просит кадры: по одному в
секунду с собственного `/image.jpg` majestic, пока облако не скажет, что увидело достаточно. Облако
ищет в них людей, машины и животных и сообщает владельцу. Камера говорит только «смотри сейчас», с
самого момента движения: облаку не нужно ни тянуть поток, ни знать пароль RTSP.

События подписаны. В ответе на heartbeat едет `eventKey` координатора; ключ —
`HKDF-SHA256(X25519(ключ устройства, eventKey), salt = nodeId, info = "streq-events-v1")`, у каждого
запроса `X-Streq-Ts` и `X-Streq-Sig = base64(HMAC-SHA256(ключ, ts \n nodeId \n scope \n тело))`. Нового
секрета на камере не появляется: подпись живёт ровно столько, сколько ключ устройства.

Проверить на камере: `cerberus snapshot` (отдаёт ли majestic кадр по настроенному адресу) и
`cerberus motion` (эпизод, как будто кто-то прошёл мимо).

Видео через агента не идёт: релей тянет `rtsp://{overlayIp}:554/stream0` прямо с камеры по туннелю.
P2P этот агент не делает — камера остаётся на пути через хаб, который работает всегда.

## Сборка

Агент — это каталог `src/`: `src/cerberus.c` и его `Makefile`; больше для сборки и установки ничего
не нужно. `Makefile` в корне просто передаёт команды туда. Init-скрипта среди файлов нет: его несёт и
пишет сам бинарь (`cerberus init-script`), поэтому скрипт не может оказаться из другого релиза, чем
агент, которого он запускает.

```sh
make                                   # нативно, против системного mbedTLS (3.x или 2.28 LTS)
make STATIC=1                          # статически
make VERSION=1.2.0                     # версия, которую агент сообщает (по умолчанию — из src/cerberus.c)
make install DESTDIR=/tmp/rootfs       # /usr/sbin/cerberus + /etc/init.d/S99cerberus, записанный им
```

Бинари релиза собирает `ci/build.sh`, которому нужен только Docker: он скачивает musl-тулчейн
[Bootlin](https://toolchains.bootlin.com) и исходники mbedTLS (оба сверяются по sha256), собирает
статически, проверяет архитектуру ELF, а затем **запускает** каждый бинарь под QEMU и сверяет его
ключ X25519 с `wg pubkey`:

```sh
ci/build.sh                            # arm, mipsel, aarch64, x86_64 → dist/cerberus-<arch>
ci/build.sh mipsel                     # одну из них
ci/assemble.sh                         # + установщики, SHA256SUMS → релиз в dist/
```

Внутри сборки прошивки, её собственным тулчейном, указывая на `src/`:

```sh
make -C src CC=mipsel-openipc-linux-musl-gcc MBEDTLS=<buildroot-staging> STATIC=1
make -C src install DESTDIR=<target-rootfs> RUN=<host-dir>/bin/qemu-mipsel
```

`make install` получает init-скрипт, запуская собранный бинарь, а кросс-сборка сама этого не может:
дайте ей user-mode эмулятор в `RUN` (`host-qemu` из Buildroot; статическому бинарю sysroot не нужен)
или передайте `INIT_SCRIPT=no`, и пусть прошивка выполнит `cerberus init-script` на камере. Без
одного из двух установка останавливается, а не ставит агента, которого ничто не запустит.

## Тесты

```sh
make test                                                  # Alpine: musl + mbedTLS 3.x
CERBERUS_TEST_IMAGE=debian:bookworm-slim tests/run.sh      # glibc + mbedTLS 2.28
```

Нужен только Docker. Набор собирает агента с `-Werror` и гоняет его против поддельного координатора
по настоящему TLS: личность, проверка TLS, энролл, обратный канал (команды, переехавший или сменивший
ключ хаб, недоступность координатора, отозванный узел), отступ на старте, миграция `streq_*` на
поддельном U-Boot env, установщик целиком из релиза, разложенного на диске, — и настоящий
kernel-WireGuard туннель до хаба в отдельном network namespace, включая украденный маршрут, который
проба внутри туннеля должна заметить и починить. Для data plane на хосте нужен kernel WireGuard;
`REQUIRE_WG=1` делает его отсутствие провалом — так запускает CI.

## CI и релизы

На каждый push и pull request — shellcheck, тесты на обоих поколениях mbedTLS и четыре сборки релиза.
Когда push в `master` приносит новую `CERBERUS_VERSION` (`src/cerberus.c`), CI заменяет единственный
релиз `latest` этими же бинарями вместе с установщиками, лицензией и `SHA256SUMS`, с заголовком
`Cerberus <версия>`; push без новой версии ничего не публикует. Версия, вкомпилированная в бинари, —
сама `CERBERUS_VERSION`, тегов `v*` нет. Чтобы выпустить релиз, поднимите версию и добавьте её раздел
в `CHANGELOG.md` в pull request, затем смержите его.

Версия — `MAJOR.MINOR.PATCH` (`CERBERUS_VERSION` в `src/cerberus.c`): PATCH — исправления и мелкие
правки, MINOR — новая возможность, MAJOR — несовместимое изменение или крупное обновление, только по
решению сопровождающего. PR, который меняет `src/`, установщики, `Makefile` или `ci/`, поднимает
версию последним коммитом перед мержем вместе с её разделом в `CHANGELOG.md`; правки документации,
тестов и workflow в `.github/` версию не поднимают. CI проверяет это в каждом PR
(`.github/check-version.sh`).
